Panel 1 — Introduction & Models
Introduction: Using Claude

Definition: Claude is a family of large language models (LLMs) that read, write, code, and reason over very long text and images — for knowledge work, coding, and decisions.

Versions: the current Claude 4.x family is Haiku 4.5, Sonnet 4.6, and Opus 4.7 — different speed, cost, and reasoning strengths.

Access —

  1. Claude.ai — browser chat + Projects + Artifacts.
  2. Claude Code — coding environment wired to files and repos.
  3. Claude API / platform — programmable access via SDKs.

Goals when using Claude —

  1. Clarify your objective — what decision, asset, or outcome?
  2. Give enough context — documents, examples, constraints.
  3. Specify the output format — bullets, tables, SOPs, code.
  4. Iterate — review, critique, refine; don't expect perfection first try.
Claude Models — Quick Reference

Opus 4.7 — Deep Thinking: complex reasoning, strategy, research synthesis; multi-step plans; non-trivial coding across many files. Pick when quality > speed or problems are ambiguous.

Ex: "You are my strategy partner. Read these docs and design a 90-day plan for [goal]; highlight trade-offs, risks, assumptions."

Sonnet 4.6 — Default Workhorse: everyday writing, editing, summarizing, support drafts, docs, checklists — most SMB workflows. The default for Claude.ai & Projects.

Ex: "Rewrite this for busy SMB owners in a clear, friendly tone: 2-sentence summary + 5 bullets."

Haiku 4.5 — Speed & Volume: bulk classification, tagging, extraction; fast Q&A; high-volume tasks where cost/speed matter most.

Ex: "For each review, output: name, sentiment, main complaint, recommended response angle."

Core Concepts & Terminology

Context window: the total text + images Claude can consider at once — very long (hundreds of pages in one go on top models).

System instructions: persistent directions that set Claude's role, tone, and rules. Ex: "You are my pragmatic AI coach for SMBs doing $500K–$5M; give practical next steps, no theory."

Projects: persistent workspaces that store docs, instructions, and chats for a client or topic — long-term memory + shared context.

Artifacts: a side-by-side panel where Claude renders live, editable outputs (code, docs, UIs, tables) instead of plain chat.

Claude Code: a coding environment that reads, edits, and generates code across files and repos.

Beginner: How to Talk to Claude

Basic prompt framework —

  1. ROLE — who Claude should be.
    1. "You are my [expert type]…"
  2. GOAL — what you want done.
    1. "Your goal is to [outcome]…"
  3. INPUT — paste/upload all context.
    1. "Here is the context: [text/files]."
  4. OUTPUT FORMAT — how to answer.
    1. "Return: summary, 5 bullets, a table."

Ask-then-answer — "Before answering, ask up to 5 clarifying questions, then propose a plan and execute." — cuts hallucinations.

Constraints & style — length ("≤200 words"), tone ("plain, warm, confident"), audience ("busy SMB owners").

Iteration loop — draft → critique ("what's missing / generic?") → revise ("v2: keep structure, add specifics") → save to a library/Project.

Panel 2 — Claude.ai, Projects & Artifacts
Claude.ai — Everyday Interface

What you see — chat pane (Sonnet/Opus/Haiku) · sidebar (Projects + history) · Artifact panel (live outputs).

When to use it — ad-hoc questions & drafting · long-running work as Projects · content/doc workflows via Artifacts.

Projects — Long-Term Co-Worker Space

A project has — a name + description; its own instructions; uploaded docs; history of chats & Artifacts.

When to create one — per client/account; per product/course; per ops area (Marketing, Sales Scripts, SOP Library, Hiring).

Setup template —

  1. Name it: "Claude for SMB Owners — Core Playbooks."
  2. Upload:
    1. offers, pricing, services
    2. best emails, posts, pages
    3. ICP & customer research
    4. SOPs (marketing, sales, ops)
  3. Instructions: "You are our in-house AI strategist; write for SMB owners ($500K–$5M), practical, no hype."
  4. Default model: Sonnet 4.6 daily; Opus 4.7 for strategy.

Recipes — "Write a 1-page brief of our audience/offers/positioning, then 10 matching content topics." · "Consolidate all onboarding SOPs into one; flag contradictions."

Artifacts — Live Workspaces

What they hold — code (HTML/JS/Python) · formatted docs · tables, forms, simple UIs. Persistent in Projects.

When to use — pages (landing, email, PDF) · scripts & prototypes · internal tools (checklists, calculators).

Workflow — create ("make an Artifact that…") → inspect & edit directly → export/reuse (copy to your site; save in Project).

Examples — a one-page prompt library by role · an SOP generator (Task/Owner/Tools/Frequency → formatted SOP) · a content calendar table.

Everyday Prompt Recipes

Email/comms — "Turn this thread into: a decision summary, a client-facing email, and an internal recap (who/what/when)."

Meetings — before: "3 decisions, 5 questions, 3 risks." after: "Decisions, Action Items (owner+due), Risks, Follow-ups."

Repurposing — "From this article: 3 LinkedIn posts, 3 email teasers, a 10-slide outline."

Decisions — "As a skeptical advisor, critique this plan: assumptions, failure modes, early warning signs, 3 safer alternatives."

Panel 3 — Claude Code & Cowork Workflows
Claude Code — Overview

Definition: a coding-focused Claude that connects to your repos, files, and terminal to read, explain, modify, and generate code with deep context.

Goals — speed up onboarding to a codebase · safe multi-file changes (plans, diffs, tests) · offload repetitive work with human review.

Claude Code — Core Capabilities

Code understanding — explain unfamiliar files; answer "where is X?", "what calls Y?", "what breaks if I change Z?"

Refactor & features — plan + implement across files; generate tests; propose safer patterns incrementally.

DevOps & scripts — write/modify shell, CI/CD, IaC; debug failing jobs from logs + configs.

Claude Code — Prompt Patterns

Repo map — "Scan this repo: architecture overview, main modules + responsibilities, key data models, risky areas to change."

Plan-then-patch — 1) "propose a step-by-step plan: files, functions, tests." 2) "implement steps 1–3; diff-style output only; no destructive commands."

Review mode — "As a senior engineer, review this diff for correctness, readability, performance, security, tests — with concrete suggestions."

Guardrails — "Explain changes plainly; keep them small; preserve style; update tests; ask before destructive commands (rm, DROP TABLE)."

Cowork Style — Claude + You + Your Stack

Version control — "Summarize these commits as a PR description (context, intent, risk)." · "Generate a changelog entry from this diff."

CI/CD — "Propose a GitHub Actions pipeline (lint, test, build, staging deploy) for our stack." · "Why is this job failing — minimal fix?"

Non-dev teammates — Artifacts with simple forms: paste ticket → drafted reply + tag; paste CSV → cleaned data + metrics + anomalies.

SMB Owner Playbook — Examples

Owner brief — "From this month's P&L + notes: a 1-page owner brief (what changed, why, watch), 3 questions for my accountant, 3 team actions."

Client summary — "From these transcripts/threads for Client X: status, open promises (owner+due), risks/blockers, next 3 moves."

Template builder — "Turn this top email into a reusable template with marked variables + 3 filled examples for different industries."

Policy/SOP upkeep — "Compare legacy SOPs with the new process doc: list conflicts, produce one updated SOP, suggest 3 adoption metrics."

Owner's Week With Claude

Mon — plan the week from last week's notes.

Tue — draft a week of content from one idea.

Wed — review pipeline; draft follow-ups.

Thu — clean up ops: SOPs, vendor emails.

Fri — recap wins; prep next week's list.

More Code Recipes

Tests — "Write unit tests for this module; cover edge cases."

Docs — "Generate a README + inline comments for this file."

Migrate — "Port this script from [X] to [Y]; keep behavior identical."

Explain an error — "Walk me through this stack trace and the smallest safe fix."

Safety & Governance

Keep a human approval step on anything customer-facing or legal.

Strip PII, card & bank data before pasting.

Verify every number, date, name, and citation.

Never auto-send unread output; disclose AI where required.
